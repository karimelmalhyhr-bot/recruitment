# مِعيار — منصة التوظيف لفريق HR

منصة داخلية لإدارة الوظائف والمرشحين ومسار الاختيار والمكالمات والمقابلات والأسئلة والتقييمات. القرار النهائي يظل بيد فريق الموارد البشرية؛ لا يصدر النظام قرار رفض أو تعيين آلياً.

## تشغيل المشروع

- `pnpm dev`: تشغيل خادم التطوير والواجهة على المنفذ 3000 (أو `PORT` الذي يحدده المشروع).
- `pnpm check`: فحص TypeScript.
- `pnpm test`: تشغيل اختبارات التطبيق.
- `pnpm build`: بناء الواجهة وخادم الإنتاج.
- `pnpm db:migrate`: تطبيق الترحيلات المحفوظة.

المشروع مبني باستخدام React وExpress وtRPC وDrizzle وMySQL المُدارة. التطوير والإنتاج يستخدمان قاعدة المشروع نفسها. تُحفظ السير الذاتية في التخزين المُدار، ولا تُحفظ ملفات المرشحين في Git.

## تسجيل الدخول وتفعيل فريق HR

يستخدم الموقع Manus OAuth. لا يملك الحساب الجديد صلاحية HR تلقائياً؛ يظهر له وصول معلّق حتى يوافق المسؤول. يُحدد الحساب المسؤول عبر القيمة المحمية `HR_ADMIN_EMAIL` المطابقة لبريد Manus OAuth، ولا توضع هذه القيمة في الملفات أو المستودع. بعد دخول المسؤول، يمكنه من الإعدادات منح عضو الفريق دور `hr_member` أو `viewer` (للقراءة فقط) وسحب صلاحياته. لا يمكن ترقية حساب إلى مسؤول من لوحة الفريق.

قبل استخدام بيانات حقيقية، اضبط ظهور المشروع من إعدادات المشاركة ليكون للمالك أو الفريق فقط، وفعّل المسؤول المقصود. يتيح ذلك طبقة وصول خارجية بالإضافة إلى مصادقة التطبيق وصلاحياته.

## تقديم المرشحين

- صفحة تقديم عامة: `/apply`، أو `/apply/<jobId>` لوظيفة محددة.
- يلزم قبول إشعار الخصوصية لإرسال الطلب. الحد الأقصى للسيرة الذاتية 5 ميغابايت، والأنواع المقبولة PDF وDOC وDOCX.
- يمنع النظام تكرار البريد الإلكتروني نفسه للوظيفة ذاتها. يمكن للشخص التقديم لوظائف مختلفة.

## ربط فورم خارجي عبر Webhook

مزود الفورم لم يُحدد بعد؛ لذلك يدعم الموقع استقبالاً عاماً لا يدّعي وجود موصل مباشر إلى مزود بعينه. من صفحة **التكاملات** داخل الحساب المصرح:

1. أنشئ Webhook وحدد الوظيفة إن رغبت.
2. انسخ عنوان الاستقبال `/api/intake/<integrationId>` ورمز التكامل عند إنشائه؛ يُعرض الرمز مرة واحدة فقط.
3. اجعل الأداة التي تدير الفورم ترسل طلب `POST` إلى عنوان الموقع الكامل مع `Content-Type: application/json` والترويسة `X-HR-Integration-Token: <token>`.
4. أرسل الحقول بهذا الشكل، مع موافقة المرشح الصريحة:

```json
{
  "name": "الاسم الكامل",
  "email": "candidate@example.com",
  "phone": "+20...",
  "jobId": 1,
  "source": "اسم الفورم أو المصدر",
  "privacyAccepted": true
}
```

`jobId` مطلوب إذا لم تُربط الوظيفة في إعداد التكامل. لا يقبل الاستقبال وظيفة مغلقة أو طلباً بلا موافقة. سير العمل العام عبر Webhook لا يرفع السيرة الذاتية؛ استخدم صفحة التقديم المدمجة لذلك. طريقة الربط المباشرة تختلف حسب المزود (قد تتطلب API أو Apps Script أو وسيط أتمتة)، ولا تُفعّل وصلة خاصة قبل تحديد اسم المزود.

## الخصوصية والتشغيل

- سجلات HR ومرفقاتها تتطلب حساباً معتمداً. لا تضع بيانات حقيقية للمتقدمين في بيانات تجريبية أو ملفات المشروع.
- التوكنات والرسائل السرية تبقى في إعدادات المشروع المحمية؛ لا تُحفظ في README أو Git.
- التزم بسياسة الاحتفاظ بالبيانات المعتمدة في شركتك، وراجع صلاحيات المشاركة قبل إضافة مستخدمين.
